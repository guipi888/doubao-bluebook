## 21.7 理论要点：从 Agent Loop 到 Durable Workspace

### 21.7.1 核心转变

**从"对话"到"工作空间"**：
- 传统：每次新开对话，上下文丢失
- Codex：持久线程，状态持续积累

**从"单次响应"到"持续工作"**：
- 传统：输入 → 输出，完成
- Codex：目标 → 分解 → 执行 → 验证 → 持续迭代

## 21.8 核心机制解析

### 21.8.1 Durable Thread（持久线程）

**实现**：
- 会话状态持久化到数据库
- 上下文跨会话保持
- 自动摘要和压缩

**数据结构**：
```json
{
  "thread_id": "uuid",
  "created_at": "2026-07-10T09:00:00+08:00",
  "updated_at": "2026-07-10T17:00:00+08:00",
  "context": {
    "project": "ai-hotspot",
    "preferences": {...},
    "history": [...]
  },
  "state": "active",
  "metadata": {
    "model": "gpt-5.5",
    "total_tokens": 50000
  }
}
```

### 21.8.2 Agent Loop（智能体循环）

```
用户输入
  ↓
构建 Prompt（系统 + 开发 + 用户 + 工具）
  ↓
模型推理（Responses API）
  ↓
输出类型判断
  ├── 文本回复 → 结束
  └── 工具调用 → 执行工具 → 附加结果 → 回到推理
```

### 21.8.3 并行 Agent（Fan-out）

```
主任务
  ↓
分解为子任务
  ↓
并行启动多个 Agent
  ├── Agent 1：功能开发
  ├── Agent 2：测试编写
  ├── Agent 3：文档生成
  └── Agent 4：安全审计
  ↓
各 Agent 在独立 git worktree 工作
  ↓
汇总结果，合并到主分支
```

## 21.10 关键启示

| 启示 | 说明 | 对豆包工作流的借鉴 |
|------|------|-------------------|
| **持久线程** | 重要任务使用固定线程 | 长期项目使用固定对话 |
| **Memory 外化** | 重要信息沉淀为文件 | 建立项目级配置文件 |
| **并行执行** | 多Agent同时工作 | 多数据源并行调用 |
| **Git 集成** | 版本控制 | Prompt 版本管理 |
| **工具优先** | 不同任务用不同工具 | 豆包 + MCP 组合 |
