# 质量门禁与内容过滤

> **章节**：进阶篇第2章  
> **难度**：⭐⭐ 进阶级  
> **阅读时间**：15-20 分钟  
> **核心收获**：掌握四维过滤框架，学会设计质量门禁和降级策略

---

## 4.1 理论要点：数据源可达 ≠ 内容有效

### 4.1.1 为什么需要质量门禁

数据源返回数据，不代表这些数据都值得推送。

**真实场景**：
- 数据源正常，但当日无 AI 相关内容
- 数据源返回大量泛科技内容，真正 AI 相关不足 5 条
- 同一事件在多个来源重复出现，需要合并
- 内容是几天前的旧话题，已经失去时效性

**质量门禁的价值**：在推送前设置检查点，不通过则阻断或降级。

### 4.1.2 四维过滤框架

| 维度 | 检查项 | 不合格处理 | 豆包实现方式 |
|------|--------|-----------|-------------|
| **相关性** | 是否真正属于目标领域 | 排除泛科技噪音 | Prompt 中明确定义"AI领域"范围 |
| **时效性** | 日期是否为当日 | 排除过期热点 | 检查发布日期，只保留当日 |
| **重复性** | 同一事件是否多来源出现 | 合并展示 | 按标题/核心词去重 |
| **最低数量** | 有效条目是否达到阈值 | 不足则标注或阻断 | 设置 minimum_items 阈值 |

### 4.1.3 三种质量状态

| 状态 | 定义 | 输出策略 |
|------|------|----------|
| **pass** | 有效条目 ≥ 阈值，来源充足 | 正常输出完整清单 |
| **warning** | 部分来源缺失，但有效条目充足 | 输出清单，顶部标注缺失来源 |
| **blocked** | 有效条目不足或全部来源失败 | 不推送正文，只推送说明 |

## 4.2 实战案例：四维过滤实现

### 4.2.1 场景：热点清单中混入大量泛科技内容

**问题**：原始聚合结果 45 条，但真正 AI 相关不足 5 条。

**豆包 Prompt 设计**：
```
请对聚合后的热点清单进行四维过滤：

1. 相关性：只保留真正属于 AI 领域的内容
   - ✅ 包括：AI模型发布、AI工具、AI Coding、AI测评、AI政策
   - ❌ 排除：泛科技、数码产品、互联网公司动态、普通软件更新

2. 时效性：只保留当日发布的内容
   - 检查发布日期，排除过期热点

3. 重复性：同一事件在不同来源出现时，合并为一条
   - 按标题相似度或核心关键词判断

4. 最低数量：如果过滤后有效条目少于 5 条，视为"内容不足"

输出前请说明：
- 过滤后条目数量
- 被排除的主要原因（如"10条为泛科技内容，3条为过期内容"）
- 最终状态：pass / warning / blocked
```

### 4.2.2 过滤逻辑伪代码

```python
def quality_gate(items, sources, config):
    """四维过滤"""
    passed = []
    blocked_reason = []
    
    for item in items:
        # 1. 相关性检查
        if not is_relevant(item, config["ai_keywords"]):
            blocked_reason.append(f"排除：{item.title}（非AI领域）")
            continue
        
        # 2. 时效性检查
        if not is_today(item.publish_date):
            blocked_reason.append(f"排除：{item.title}（过期内容）")
            continue
        
        # 3. 重复性检查
        if is_duplicate(item, passed):
            # 合并到已存在条目
            merge_item(item, passed)
            continue
        
        passed.append(item)
    
    # 4. 最低数量检查
    if len(passed) < config["minimum_items"]:
        return {
            "status": "blocked",
            "passed_items": passed,
            "blocked_reason": f"有效条目不足（{len(passed)}/{config['minimum_items']}）",
            "details": blocked_reason
        }
    
    # 5. 来源可用性检查
    available_sources = sum(1 for s in sources.values() if s == "ok")
    if available_sources < config["minimum_sources"]:
        return {
            "status": "warning",
            "passed_items": passed,
            "blocked_reason": f"数据源不足（{available_sources}/{len(sources)}）",
            "details": blocked_reason
        }
    
    return {
        "status": "pass",
        "passed_items": passed,
        "blocked_reason": None,
        "details": blocked_reason
    }
```

## 4.3 降级交付规则

### 4.3.1 降级决策表

| 可用来源数 | 有效条目数 | 输出策略 | 标注方式 |
|------------|------------|----------|----------|
| ≥ 3 | ≥ 5 | 输出完整清单 | 无特殊标注 |
| ≥ 3 | < 5 | 输出简化清单 | 标注"内容不足" |
| 2 | ≥ 5 | 输出简化清单 | 标注"数据不完整，仅供参考" |
| 2 | < 5 | 输出极简清单 | 标注"数据严重不完整" |
| 1 或 0 | 任意 | 不输出正文 | 只推送说明和告警 |

### 4.3.2 降级输出示例

**warning 状态**（部分来源缺失）：
```
⚠️ 数据不完整警告

可用来源：2/4
- 微信公众号：正常
- GitHub：正常
- 多引擎搜索：缺失（超时）
- AIHOT：缺失（超时）

说明：以下清单基于 2 个可用来源生成，可能遗漏部分热点。

📋 AI热点选题日报 — 2026-07-10
...
```

**blocked 状态**（有效条目不足）：
```
⚠️ AI热点选题日报 — 2026-07-10

状态：blocked
原因：有效条目不足（3/5）

今日 AI 热点信息量较低，未达到输出标准。
建议：手动检查其他数据源，或跳过今日。

下次自动触发：2026-07-11 09:00
```

## 4.5 常见错误

| 错误 | 后果 | 纠正方法 |
|------|------|----------|
| 不过滤直接输出 | 噪音内容干扰决策 | 增加四维过滤，设置最低数量阈值 |
| 内容不足仍强行输出 | 空清单或无意义内容 | 少于 5 条时进入 blocked 状态 |
| 降级后伪装完整 | 用户误以为数据齐全 | 必须显式标注缺失来源和数量 |
| 过滤维度太严格 | 有效内容被误杀 | 定期复盘过滤规则，调整关键词 |
| 忽略合并重复项 | 同一事件出现多次 | 增加重复性检查，按核心词去重 |
