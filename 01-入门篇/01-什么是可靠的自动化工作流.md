# 什么是可靠的自动化工作流

> **章节**：入门篇第1章  
> **难度**：⭐ 入门级  
> **阅读时间**：10-15 分钟  
> **核心收获**：理解"可靠"的真正含义，建立自动化设计的基本判断标准

---

## 1.1 理论要点：可靠性的四个要素

**核心公式**：
```
可靠自动化 = 固定决策 × 明确边界 × 失败兜底 × 可追溯
```

### 1.1.1 固定决策

**含义**：Prompt 结构和输出格式稳定，不会因为"随机性"导致每次结果不同。

**判断标准**：
- ✅ 手动运行 3 次，输出格式基本一致
- ✅ 输出字段固定，可以预期
- ❌ 每次结果差异巨大，无法形成固定模板

**反例**：
```
❌ "帮我找今天的AI热点" → 每次结果不同，无法固定格式
✅ "找今天的AI热点，按[标题/摘要/来源/建议角度]格式输出" → 稳定可预期
```

### 1.1.2 明确边界

**含义**：清楚知道系统做什么、不做什么、人类何时介入。

**边界定义三要素**：
1. **自动化范围**：哪些步骤自动执行
2. **人类介入点**：哪些步骤必须人工确认
3. **系统永不做什么**：明确禁区

**示例边界定义**：
```
自动化范围：
├── 数据抓取（自动）
├── 过滤去重（自动）
├── 聚合排序（自动）
└── 推送草稿（自动）

人类介入点：
└── 最终选题确认（人从清单中点选）

系统永不做什么：
├── 不代替博主判断"值不值得写"
├── 不发送未经审核的内容
└── 不修改财务数据
```

### 1.1.3 失败兜底

**含义**：任何一步都可能失败，必须有预设的应对方案。

**常见失败场景**：
| 失败类型 | 发生概率 | 应对策略 |
|----------|----------|----------|
| 数据源 API 超时 | 中 | 重试 1 次，仍失败则标记缺失 |
| 数据源返回空结果 | 低 | 标记缺失，继续其他来源 |
| API 限流（429） | 中 | 按 Retry-After 等待，最多 2 次 |
| 认证失效（401/403） | 低 | 停止重试，转人工处理 |
| 推送目标不可达 | 低 | 指数退避重试 2 次，失败则告警 |
| 聚合结果为空 | 极低 | 进入 blocked 状态，推送说明 |

### 1.1.4 可追溯

**含义**：每次运行有日志，出问题可以回查。

**必须记录的信息**：
- 批次 ID（唯一标识本次运行）
- 触发时间与触发方式（定时/手动）
- 各数据源响应状态和耗时
- 聚合条目数量（原始 → 过滤后）
- 推送目标和结果（成功/失败/message_id）
- 总耗时和错误信息
- 运行成本（Token 消耗、API 调用次数）

## 1.2 豆包的四个工作流入口

### 1.2.1 入口对比

| 入口 | 适用场景 | 上手成本 | 灵活性 | 可靠性 | 团队协作 |
|------|----------|----------|--------|--------|----------|
| **内置指令链** | 个人轻量任务 | 低 | 中 | 中 | 低 |
| **飞书多维表格联动** | 团队协作、结构化数据 | 中 | 中高 | 中高 | 高 |
| **桌面版 Alt+空格** | 即时任务、全局唤起 | 低 | 中 | 中 | 低 |
| **四大智能体模块** | 复杂多步任务 | 中高 | 高 | 高 | 中 |

### 1.2.2 选择入口的决策树

```
需要团队协作？
├── 是 → 飞书多维表格联动
└── 否 → 需要外部数据源？
    ├── 是 → WorkBuddy / MCP
    └── 否 → 内置指令链
```

## 1.3 实战案例：5分钟搭建"每日AI热点选题"任务

### 1.3.1 场景描述

作为 AI 博主，每天早上 9:00 自动获取热点清单，筛选当天选题。

### 1.3.2 步骤详解

**步骤1：手动验证 Prompt（关键！）**

先不自动化，手动运行至少 3 次，确认输出格式稳定：

```
我是AI领域博主，内容方向是AI教程、AI工具、AI Coding、AI测评。
请帮我找今日AI领域热点，方便筛选选题。

来源：
- 微信公众号近期爆款文章
- GitHub今日热门AI项目
- 多引擎AI新闻聚合
- AI热点追踪

输出格式：
1. 标题
2. 一句话摘要
3. 来源
4. 建议角度（功能测评/上手教程/观点分析）

要求：
- 只保留真正属于AI领域的内容
- 排除泛科技、数码产品、互联网公司动态
- 同一事件在不同来源出现时合并为一条
- 过滤后至少保留5条，否则标注"内容不足"
```

**步骤2：在豆包中保存为自定义指令**

1. 点击右上角"+" → 创建新指令
2. 命名为"AI热点选题日报"
3. 将上述 Prompt 粘贴进去
4. 设置触发词："启动选题任务"

**步骤3：设置定时触发**

- 在 WorkBuddy 或豆包桌面版中设置定时任务
- 触发时间：每天 09:00
- 推送目标：个人飞书通知

**步骤4：验证**

- 手动触发一次，检查输出格式是否稳定
- 确认推送到达
- 运行 3 次，确认结果符合预期

### 1.3.3 第一次自动化检查清单

```
□ 手动运行 Prompt 至少 3 次，输出格式稳定
□ 明确触发时间（如每天 9:00）
□ 明确推送目标（飞书群/个人通知/文档追加）
□ 明确 owner（谁负责处理失败）
□ 有明确的停用方法（知道怎么暂停）
□ 失败时知道找谁
```

---

## 1.4 常见错误

| 错误 | 后果 | 纠正方法 |
|------|------|----------|
| Prompt 还没稳定就自动化 | 明天就失效，需要频繁修改 | 手动运行3次，格式稳定后再自动化 |
| 没有明确推送目标 | 结果生成后找不到 | 先配置推送，再开启定时 |
| 没有 owner | 失败后无人处理 | 自动化定义模板中必须填 owner |
| 不设停用方式 | 任务出错无法暂停 | 提前在豆包/WorkBuddy 中标记停用入口 |
