> **章节**：入门篇第3章  
> **难度**：⭐ 入门级

> **核心收获**：跟着完整案例走一遍，从零到一搭建第一个可靠的自动化任务

## 6.1 理论要点：完整案例的价值

### 6.1.1 为什么需要完整案例

 isolated 的理论学习容易遗忘，跟着完整案例走一遍可以：
- 理解每个步骤的具体操作
- 看到中间产物和最终输出
- 理解常见错误的实际表现
- 建立可复用的模板

### 6.1.2 案例选择标准

本案例选择「每日AI热点选题日报」因为它：
- 场景常见：很多内容创作者都需要
- 复杂度适中：包含数据聚合、过滤、推送完整链路
- 可扩展：可以从个人使用扩展到团队协作
- 成本可控：主要使用免费数据源

## 6.2 实战案例：从零搭建"每日AI热点选题日报"

### 6.2.1 场景描述

**角色**：AI 领域博主，内容方向是 AI 教程、AI 工具、AI Coding、AI 测评。

**需求**：每天早上 9:00 自动获取前一天的 AI 热点，整理成清单，推送到飞书，方便筛选当天选题。

**成功标准**：
- 每天早上 9:00 准时收到清单
- 清单包含至少 5 条有效 AI 热点
- 格式固定，5 分钟内可以完成选题判断
- 失败时收到告警，知道如何处理

---

## 6.3 步骤详解

### 步骤1：明确需求和边界

**需求澄清**：
```
目标：筛选当日值得写的 AI 选题
输入：4个数据源（微信公众号、GitHub、搜索引擎、AIHOT）
输出：结构化热点清单
推送：飞书个人通知
频率：每天 09:00（工作日）
owner：博主本人
```

**边界定义**：
```
自动化范围：
├── 数据抓取（自动）
├── 过滤去重（自动）
├── 聚合排序（自动）
└── 推送草稿（自动）

人类介入点：
└── 最终选题确认（人从清单中点选）

系统永不做什么：
├── 不代替博主判断"值不值得写"
├── 不发送未经审核的内容
└── 不修改财务数据
```

**降级条件**：
- 数据源失效超过 2 个 → 停止自动推送，仅通知人工处理
- 有效条目不足 5 条 → 不推送空清单，推送说明

---

### 步骤2：手动验证 Prompt（关键步骤）

**先不自动化，手动运行至少 3 次**。

**Prompt 模板**：
```
我是AI领域博主，内容方向是AI教程、AI工具、AI Coding、AI测评。
请帮我找今日AI领域热点，方便筛选选题。

来源：
- 微信公众号近期爆款文章
- GitHub今日热门AI项目
- 多引擎AI新闻聚合
- AI热点追踪

输出格式：
1. 标题
2. 一句话摘要
3. 来源
4. 建议角度（功能测评/上手教程/观点分析）

要求：
- 只保留真正属于AI领域的内容
- 排除泛科技、数码产品、互联网公司动态
- 同一事件在不同来源出现时合并为一条
- 过滤后至少保留5条，否则标注"内容不足"
```

**手动运行检查清单**：
```
□ 第1次运行：检查输出格式是否符合预期
□ 第2次运行：检查是否稳定，有没有随机性
□ 第3次运行：检查过滤效果，有没有漏掉重要热点
□ 三次结果对比：格式是否一致，内容是否有重复
```

**常见问题**：
- 如果三次结果差异大 → 优化 Prompt，增加约束条件
- 如果过滤效果不好 → 调整关键词和排除规则
- 如果输出格式不稳定 → 用更严格的模板约束

---

### 步骤3：选择工作流入口

根据案例特点：
- 个人使用，不需要团队协作 → 排除飞书多维表格联动
- 需要外部数据源（微信公众号、GitHub、搜索引擎）→ 需要 WorkBuddy/MCP
- 输出格式固定，逻辑清晰 → 适合内置指令链 + WorkBuddy 自动化

**决策**：使用 WorkBuddy 自动化任务 + 豆包指令链

---

### 步骤4：配置 WorkBuddy 自动化任务

**在 WorkBuddy 中创建自动化任务**：

```
任务名称：AI 热点选题日报
触发方式：每天 09:00（工作日）
触发条件：无前置检查，定时直接运行

Prompt：
我是AI领域博主，内容方向是AI教程、AI工具、AI Coding、AI测评。
请帮我找今日AI领域热点，方便筛选选题。

来源：
- 微信公众号近期爆款文章
- GitHub今日热门AI项目
- 多引擎AI新闻聚合
- AI热点追踪

输出格式：
1. 标题
2. 一句话摘要
3. 来源
4. 建议角度（功能测评/上手教程/观点分析）

要求：
- 只保留真正属于AI领域的内容
- 排除泛科技、数码产品、互联网公司动态
- 同一事件在不同来源出现时合并为一条
- 过滤后至少保留5条，否则标注"内容不足"

数据源：
- @wechat-article-search
- @GitHub热门项目
- @多引擎搜索
- @AIHOT

质量门禁：
- 有效AI相关条目 ≥ 5条
- 数据源可用数量 ≥ 3个

输出格式：结构化热点清单（含来源、热度、建议角度）

推送目标：个人飞书通知

幂等控制：批次 ID = ai-hotspot-{date}

重试策略：
- 数据源超时重试1次
- 推送失败退避重试2次
- 其他失败转人工

告警接收：个人飞书通知
owner：博主本人
停用方式：WorkBuddy → 自动化任务管理页 → 暂停
```

---

### 步骤5：数据源就绪检查配置

**为每个数据源配置探活逻辑**：

| 数据源 | 探活方法 | 超时阈值 | 重试策略 | 不可用处理 |
|--------|----------|----------|----------|------------|
| 微信公众号 | 调用搜索 API | 10秒 | 重试1次 | 标记缺失 |
| GitHub | 调用热门项目 API | 10秒 | 429时按 Retry-After | 标记缺失 |
| 多引擎搜索 | 调用搜索 API | 10秒 | 重试1次 | 标记缺失 |
| AIHOT | 调用热点追踪 API | 10秒 | 重试1次 | 标记缺失 |

**最低可用阈值**：4个来源中至少3个正常，才输出完整结果。

---

### 步骤6：质量门禁配置

**四维过滤规则**：

1. **相关性**：
   ```
   关键词匹配：AI、人工智能、大模型、机器学习、深度学习
   排除词：数码、手机、互联网公司动态、普通软件更新
   ```

2. **时效性**：
   ```
   只保留当日发布的内容
   检查发布日期，排除过期热点
   ```

3. **重复性**：
   ```
   按标题相似度 > 80% 判断重复
   同一事件合并为一条，保留最完整的描述
   ```

4. **最低数量**：
   ```
   有效条目 < 5条 → blocked
   推送说明，不推送空清单
   ```

---

### 步骤7：推送目标配置

**推送目标**：个人飞书通知

**幂等控制**：
```
批次 ID 格式：ai-hotspot-2026-07-10
推送前检查：该批次是否已推送？
- 是：跳过推送，记录"已跳过"
- 否：执行推送，记录 message_id
```

**推送内容格式**：
```
📋 AI 热点选题日报 — 2026-07-10

【今日概况】
有效条目：18 条 | 来源：4/4 | 运行时间：09:02

━━━━━━━━━━━━━━━━
🔥 高热度（适合快速行动）
1. [标题] — 来源：A + B
   热度指数：★★★★★ | 建议角度：xxx

━━━━━━━━━━━━━━━━
📈 潜力方向（适合深度分析）
...

━━━━━━━━━━━━━━━━
⚠️ 数据来源说明
来源A：正常 | 来源B：缺失（超时）| 来源C：正常
```

---

### 步骤8：告警配置

**告警接收**：个人飞书通知

**告警内容模板**：
```
⚠️ AI 热点选题任务告警

批次：ai-hotspot-2026-07-10
状态：Blocked
触发时间：09:00
失败原因：所有数据源均返回空结果或超时
已完成步骤：fetching（部分失败）
影响：今日热点清单未生成，未推送

建议处理：
1. 检查各数据源 API 状态
2. 如为临时故障，可手动触发一次任务重跑
3. 如需跳过今日，确认后标记为已处理

恢复入口：WorkBuddy → 自动化任务 → 手动运行
```

---

### 步骤9：手动验证和调整

**验证步骤**：
1. 手动触发一次任务
2. 检查输出格式是否符合预期
3. 检查推送是否到达
4. 检查日志是否完整

**调整 checklist**：
```
□ 输出格式是否固定？
□ 过滤效果是否满意？
□ 推送是否及时？
□ 失败时告警是否清晰？
□ 耗时是否在可接受范围？
```

---

### 步骤10：开启定时运行

**上线前最终检查**：
```
□ 手动运行3次，输出稳定
□ 推送目标配置正确
□ 告警接收人配置正确
□ owner 明确
□ 停用方式已知
```

**开启定时**：
- WorkBuddy → 自动化任务 → 找到"AI热点选题日报"
- 点击"启用"
- 设置生效时间：次日 09:00

## 6.6 常见错误

| 错误 | 后果 | 纠正方法 |
|------|------|----------|
| 未手动验证就自动化 | 定时运行后才发现问题 | 必须手动运行3次，确认稳定后再自动化 |
| 边界定义模糊 | 任务执行超预期或不足 | 写清楚"系统做什么/不做什么/人类何时介入" |
| 数据源检查缺失 | 某源失败导致整体崩溃 | 配置探活逻辑，设置最低可用阈值 |
| 质量门禁太松 | 噪音内容干扰决策 | 设置四维过滤，配置最低条目阈值 |
| 幂等控制缺失 | 重复触发导致重复推送 | 生成批次ID，推送前检查是否已推送 |
| 告警配置错误 | 失败后无人知晓 | 配置明确的告警接收人和内容模板 |
