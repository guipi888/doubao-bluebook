## D.1 入门阶段常见问题

### Q1：第一次做自动化，从哪里开始？

**A**：建议从最简单的任务开始：
1. 选择一个你每天都要做、步骤固定的任务
2. 手动运行至少3次，确认输出稳定
3. 使用内置指令链保存 Prompt
4. 配合 WorkBuddy 设置定时任务
5. 运行一周，观察效果

**参考章节**：第1章、第2章、第6章

---

### Q2：Prompt 怎么写才能稳定输出？

**A**：稳定输出的关键：
1. **明确角色**："你是AI领域的内容助手"
2. **明确任务**："请帮我找今日AI热点"
3. **明确输入**："来源：微信公众号、GitHub..."
4. **明确输出格式**："输出JSON格式：{title, summary, source, angle}"
5. **明确约束**："只保留AI相关，排除泛科技"
6. **手动验证3次**：确认稳定后再自动化

**参考章节**：第1章、第6章

---

### Q3：数据源超时怎么办？

**A**：配置重试策略：
1. 设置超时阈值（如10秒）
2. 超时后等待10秒重试1次
3. 仍失败则标记为"缺失"
4. 继续处理其他数据源
5. 在输出顶部标注缺失来源

**参考章节**：第3章、第7章

---

### Q4：推送重复了怎么办？

**A**：配置幂等控制：
1. 每次运行生成唯一批次 ID（如 `ai-hotspot-2026-07-10`）
2. 推送前检查该批次是否已推送
3. 已推送则跳过，记录"已跳过"
4. 未推送则正常执行

**参考章节**：第3章、第9章

---

## D.2 进阶阶段常见问题

### Q5：状态机怎么设计？

**A**：状态机设计步骤：
1. 列出所有可能的状态（Idle、Triggered、Fetching...）
2. 定义每个状态的进入条件
3. 定义每个状态的成功出口和失败出口
4. 画出状态流转图
5. 实现状态文件持久化

**参考章节**：第3章、第8章

---

### Q6：质量门禁怎么配置？

**A**：四维过滤框架：
1. **相关性**：定义 AI 领域关键词和排除词
2. **时效性**：只保留当日发布的内容
3. **重复性**：按标题相似度 > 80% 去重
4. **最低数量**：有效条目 < 5 条则 blocked

**参考章节**：第4章、第11章

---

### Q7：如何控制成本？

**A**：成本控制策略：
1. 设置单次运行成本上限（如 ¥0.10）
2. 优化 Prompt，减少 Token 消耗
3. 使用模型路由（简单任务用小模型）
4. 缓存热点数据，减少重复调用
5. 记录每次运行的实际成本

**参考章节**：第5章、第14章

---

### Q8：日志怎么记录？

**A**：必须记录的信息：
- 批次 ID
- 触发时间和方式
- 各数据源响应状态和耗时
- 聚合条目数量（原始 → 过滤后）
- 推送目标和结果
- 总耗时和错误信息
- Token 消耗和成本

**参考章节**：第5章、第13章

---

## D.3 专家阶段常见问题

### Q9：如何从个人工具扩展到团队服务？

**A**：团队化扩展步骤：
1. 明确 owner 和 backup
2. 建立运行手册
3. 设置权限（谁能修改配置）
4. 制定变更流程（修改需测试后生效）
5. 配置团队推送目标（群 + 分类频道）
6. 建立审核流程（主编确认后分发）

**参考章节**：第6章、第15章

---

### Q10：多 Agent 编排怎么实现？

**A**：多 Agent 架构：
1. **Planner**：分解任务、分配子任务
2. **Executor**：执行具体任务（并行）
3. **Aggregator**：合并结果
4. **Filter**：质量过滤
5. **Formatter**：格式化输出
6. **Deliver**：推送结果

**通信方式**：消息队列或事件总线

**参考章节**：第7章、第16章

---

### Q11：Prompt 迭代怎么管理？

**A**：Prompt 版本管理：
1. 使用语义化版本号（v1.0, v1.1, v2.0）
2. 维护 changelog，记录每次变更
3. 变更后手动验证3次
4. 使用 A/B 测试验证效果
5. 保留历史版本，支持回滚

**参考章节**：第8章、第18章

---

### Q12：渐进式迁移怎么设计？

**A**：四阶段迁移：
1. **阶段0**：现状评估，确定优先级
2. **阶段1**：单点自动化，验证效果
3. **阶段2**：流程串联，增加状态管理
4. **阶段3**：智能化，反馈闭环
5. **阶段4**：规模化，团队化部署

**每阶段必须有明确的验证标准**，通过后才能进入下一阶段。

**参考章节**：第9章、第19章

---

## D.4 故障排查常见问题

### Q13：任务突然不执行了？

**A**：排查步骤：
1. 检查定时任务是否启用
2. 检查豆包/WorkBuddy 服务是否正常
3. 查看日志，是否有报错
4. 检查数据源是否可用
5. 检查是否有配置变更

---

### Q14：输出格式突然变了？

**A**：可能原因：
1. Prompt 被修改
2. 豆包模型升级，行为变化
3. 数据源返回格式变化

**解决方法**：
1. 检查 Prompt 版本
2. 手动运行，观察输出
3. 调整 Prompt 或添加格式约束
4. 更新版本记录

---

### Q15：成本突然飙升？

**A**：排查步骤：
1. 检查 Token 消耗是否异常
2. 检查是否有无限重试
3. 检查 Prompt 是否过长
4. 检查数据源调用频率
5. 设置成本上限和告警

## D.5 工具选型常见问题

### Q16：豆包 vs Claude Code 怎么选？

**A**：选型建议：
- **豆包**：通用场景、内容创作、团队协作、学习成本低
- **Claude Code**：软件开发、代码生成、需要本地部署、对安全性要求高

**参考章节**：第17章

---

### Q17：什么时候需要 WorkBuddy/MCP？

**A**：需要 WorkBuddy/MCP 的场景：
1. 需要调用外部数据源（非豆包内置）
2. 需要复杂的状态管理和错误处理
3. 需要跨应用集成
4. 需要团队化协作
5. 需要详细的监控和日志

**参考章节**：第1章、第2章

---

## D.6 其他常见问题

### Q18：自动化任务多久需要维护？

**A**：维护频率：
- **每日**：检查告警和日志
- **每周**：复盘数据，收集反馈
- **每月**：评估指标趋势，优化 Prompt
- **每季度**：评估架构，考虑扩展

---

### Q19：团队对自动化有抵触怎么办？

**A**：应对策略：
1. **从小处着手**：先自动化最痛的点
2. **展示价值**：用数据说话（节省时间、减少错误）
3. **保留控制权**：关键决策仍由人控制
4. **培训支持**：教会团队如何使用
5. **逐步推广**：成功案例后再推广

---

### Q20：如何评估自动化效果？

**A**：评估指标：
- **时间节省**：自动化前后耗时对比
- **错误率**：人工错误 vs 自动化错误
- **一致性**：输出质量稳定性
- **可扩展性**：能否快速复制到其他场景
- **用户满意度**：使用者的反馈
